## 1. دعم اللغة العربية/الإنجليزية (i18n) — رسائل + محتوى

### أ) رسائل النظام (نجاح/خطأ/validation)
الباك إند بيقرأ هيدر `Accept-Language` من كل request ويرجّع كل الرسائل (نجاح، خطأ، أخطاء التحقق من البيانات) باللغة المطلوبة.

```
Accept-Language: ar
```
أو
```
Accept-Language: ar-EG,ar;q=0.9,en;q=0.8
```

- **اللغة الافتراضية إنجليزي.** لو مبعتش الهيدر، أو بعت لغة مش مدعومة، هيرجع إنجليزي دايمًا.
- بترجع هيدر `Content-Language` في الـ response يقولك اللغة اللي اتحددت فعليًا.
- كل مفاتيح الرسائل (`en.json`/`ar.json`) اتأكد إنها متطابقة 100% (440 مفتاح في الاتنين) — مفيش أي رسالة هترجع إنجليزي رغم إنك طلبت عربي.

### ب) محتوى البيانات نفسه (مش بس رسائل النظام)
دي الإضافة الأهم: **الحقول النصية الأساسية بقت مخزّنة بلغتين فعليًا في قاعدة البيانات**، مش بس واجهة الترجمة. كل حقل زي `title` بقى له نسختين:

```json
{
  "title_ar": "مقدمة في الجبر",
  "title_en": "Introduction to Algebra"
}
```

**عند الإنشاء/التعديل (POST/PATCH):** ابعت `title_ar` (إجباري) و`title_en` (اختياري، بيرجع فاضي لو معملتوش).

**عند القراءة (GET):** الباك إند بيرجّعلك حقل واحد بس اسمه `title` (من غير `_ar`/`_en`) — القيمة بتتغيّر حسب `Accept-Language`، لكن **اسم المفتاح في الـ JSON ثابت** سواء طلبت عربي أو إنجليزي. يعني الفرونت بيقرا `data.title` عادي من غير أي شرط `if (lang === 'ar')`. لو مفيش نسخة باللغة المطلوبة، بيرجع النسخة التانية بدل ما يرجع فاضي.

> ملاحظة: في شاشات الأدمن (تعديل كورس مثلًا) الـ response بيرجّع الحقلين الخام (`title_ar`, `title_en`) **زيادة على** الحقل المُجمّع `title` — عشان الأدمن يقدر يعدّل اللغتين مع بعض.

### الجداول اللي بقت ثنائية اللغة

| الموديل | الحقول |
|---|---|
| الكورسات (`courses`) | title, description |
| المحاضرات (`lectures`) | title, content |
| المراحل العمرية (`ranks`) | name, stageName |
| المدونة/الأخبار (`post`) | title, excerpt, content |
| الواجبات (`homework`) | title, description |
| الامتحانات (`exam`) | title |
| أسئلة الامتحان (`exam_question`) | text |
| خيارات السؤال (`exam_option`) | text |
| السياسات (`policy`) | title, description |
| تنبيه السياسات (`policy_notice`) | title, content |
| مقالات الدعم (`support`) | title, description |
| تصنيفات الدعم (`support_category`) | title |

## 2. البحث والفلترة في الكورسات

باراميتر `search` بيدور في: العنوان (بلغتين) + الوصف (بلغتين) + الكلمات المفتاحية + اسم التصنيف (بلغتين) في نفس الوقت:
```
GET /materials/courses?search=algebra
```
وفيه حقل جديد `keywords` (مصفوفة نصوص) على الكورس.

---

## 3. نظام الامتحانات (Exams) — إصلاحات أمنية ومنطقية

- **ترتيب عشوائي للأسئلة**: `GET /exams/:id/questions` بيرجّع ترتيب عشوائي لكل طالب، لكن ثابت لنفس الطالب على مدار المحاولة (مش بيتغيّر مع كل refresh).
- **ثغرة أمنية اتصلحت (IDOR)**: كان أي طالب يقدر يجيب بيانات امتحان طالب تاني بس بمعرفة الـ ID (`GET /exams/exam/:id`). دلوقتي بيتفحص ملكية الامتحان.
- **`duration` بقى إجباري** عند الإنشاء (كان بيسبب خطأ سيرفر 500 لو اتسيب فاضي).
- حالات الامتحان (`status`) اتوحّدت: `pending`, `in_progress`, `submitted`, `graded`.

---

## 4. حذف "المرحلة العمرية" (Ranks) — حماية من الحذف الخطير

حذف Rank مرتبط بكورسات أو طلاب دلوقتي بيرفض بخطأ `RANK_IN_USE` (409) بدل ما يمسح الكورسات والمحاضرات المرتبطة بيها تلقائيًا.

---

## 5. طلبات السحب المالي (Withdrawals) — إصلاح سباق (race condition)

- عند فتح طلب سحب: بيتحسب الرصيد **المتاح فعليًا** (الرصيد ناقص أي طلبات معلّقة تانية).
- عند الموافقة: خصم الرصيد بقى atomic، فمينفعش طلبين يتخصموا من نفس الرصيد القديم في نفس اللحظة.

---

## 6. تقارير المعاملات المالية (Transaction Stats)

`GET /transactions/stats` بقى بيطبّع كل معاملة لعملتها الصحيحة قبل الجمع، بدل ما يجمع أرقام من عملات مختلفة كأنها نفس العملة.

## 7. Blog / News — موديول جديد بالكامل

جدول `post` بحقل `type` (`blog` أو `news`).

| Method | Route | الوصول |
|---|---|---|
| GET | `/posts` | عام (بدون تسجيل دخول) — فلترة بـ `type`, `published`, `search`, `page`, `limit` |
| GET | `/posts/slug/:slug` | عام — صفحة المقالة، بيزوّد عداد القراءة |
| GET | `/posts/:id` | أدمن فقط — يشمل المسودات (drafts) |
| POST | `/posts` | أدمن فقط |
| PATCH | `/posts/:id` | أدمن فقط |
| DELETE | `/posts/:id` | أدمن فقط |

**الإنشاء/التعديل/الحذف مقصور على الأدمن فقط** — مفيش أي endpoint يسمح لليوزر العادي ينشئ بوست. القراءة عامة لأي زائر للموقع.

الـ `slug` بيتولّد تلقائيًا من `title_ar`، ولو فيه تكرار بيضيف رقم (`عنوان-2`).

## 8. حاجات معروفة ولسه محتاجة قرار/تنفيذ (خارج نطاق الشغل النهاردة)

1. **الباسورد بيتخزن بتشفير AES قابل للعكس مش bcrypt حقيقي.**
2. **`getSubscriptionRequests` بيرجّع باسوردات المستخدمين بعد فك التشفير** — تسريب بيانات فعلي.
3. **IDOR في نظام الجدولة (Schedules)** — أي حد يقدر يعمل join/leave لأي جلسة مش بتاعته.
4. **حذف جلسة جماعية بيرجع الفلوس لطالب واحد بس** مش لكل المجموعة.
5. **معلم مابياخدش فلوس أي حصة "معادة" (rescheduled)** — بيأثر على مرتبات المعلمين مباشرة.
6. **نموذج الامتحان مربوط بطالب واحد بس مفيهوش `courseId`** — تغيير أكبر في الـ schema.
7. **مفيش أي تكامل حقيقي مع Zoom API.**
8. **مفيش frontend في المستودع** — Backend فقط (Express API)، موثّق بـ Swagger.
9. **بعض ملفات توثيق Swagger** (materials, exams, homework, policies, support) لسه بتوثّق أسماء الحقول القديمة (`title` بدل `title_ar`/`title_en`) — التوثيق قديم بس الـ API نفسه شغال بالحقول الجديدة الصح. محتاج تحديث لاحقًا عشان ميحصلش لبس لمطور الفرونت.

## 9. ملاحظة تقنية

- Node.js + Express + Prisma ORM على **PostgreSQL** (مش MongoDB زي ما كان مكتوب في المستند الأصلي).
- الاعتماد الأساسي لأي طلب: `Authorization: Bearer <token>` + `Accept-Language: ar` أو `en`.
- استخدم ملف `Full_Changes.postman_collection.json` المرفق — فيه كل الـ endpoints اللي اتغيّرت/اتضافت مع أمثلة body جاهزة بالحقلين `_ar`/`_en`.
